# ESTERRA — 10 заранее подготовленных запусков Codex

**Автор плана — ChatGPT. Codex выполняет задания и сообщает факты; не придумывает следующие промпты.** Результат каждого запуска может потребовать корректировки следующих заданий. 10 запусков не гарантируют готовности без проверки, инфраструктуры, доступов и исправлений.

## Постоянные правила (в каждом запуске)
Работай ТОЛЬКО в `romariotts94-art/create-site-app`, ветка `main`. Сайт `esterra` — отдельный продаваемый продукт внутри существующего каталога. Не трогай Nova Estate и другие сайты, не создавай другие репозитории, не создавай ветки и pull request; все изменения коммить непосредственно в main. Прочитай `AGENTS.md`, `docs/UNIVERSAL_SITE_FACTORY.md`, `docs/PREMIUM_STUDIO_DESIGN_STANDARD.md` и этот файл. Прежде чем менять код, прочитай `docs/sites/esterra/PROJECT_STATE.md`, если существует, и проверь фактический код. После запуска обнови `PROJECT_STATE.md`, `FEATURE_MATRIX.md`, `REVIEW_REPORT.md` с точными результатами тестов, коммитом, блокерами и следующим этапом. Применяй семь ролей Researcher, Product Director, Art Director, Builder, QA, Security Reviewer, Fixer; если независимые агенты недоступны, не называй собственную проверку независимой. Не делай заглушки или фальшивые успешные действия. Внешние интеграции без ключей оставляй явно неактивными, с инструкцией подключения. Пиши production-код, тестируй реальные сценарии. Дизайн: единый сдержанный дорогой студийный минимализм, качественные лицензированные изображения, без цветового хаоса; визуальная проверка только по реальным скриншотам. Каждый этап заверши отчётом IMPLEMENTED / VERIFIED / ISSUES / NEXT / QUALITY GATE. **Не генерируй промпт следующего этапа — он уже написан здесь.** Не объявляй READY без доказательств.

## После десятого запуска
Если QUALITY GATE = NOT READY, продолжить дополнительными задачами по конкретным блокерам из PROJECT_STATE, а не бесконечно повторять весь план. Владелец продукта утверждает реальный контент, юридические документы, договорные правила, инфраструктуру и ключи внешних сервисов. Только после проверки реального окружения допустим статус READY FOR HANDOFF.

## Обязательная интеграция в существующий маркетплейс (начиная с запуска 1)
ESTERRA должен появиться **в каталоге уже существующего приложения create-site-app**, а не только в репозитории или отдельной папке. Найди действующий источник данных карточек каталога, маршрутизацию, экран предпросмотра и существующую схему превью; зарегистрируй ESTERRA тем же способом, что и остальные сайты. Добавь карточку с названием ESTERRA, категорией «Недвижимость», корректным превью и действием «Открыть сайт». Клик обязан открывать реально работающую текущую сборку ESTERRA внутри существующего механизма предпросмотра (либо через предусмотренный проектом URL), с рабочей навигацией и возвратом в каталог. Не создавай второй каталог и не ломай другие карточки. Добавь проверку каталога и перехода к ESTERRA в тесты и в каждый последующий регрессионный прогон. Если для доступа нужен деплой/публичный URL, подготовь конфигурацию и честно отметь необходимость публикации; не подставляй фиктивный адрес. **Готовность этапа 1 требует:** карточка видна в каталоге, переход работает в доступной среде, а все существующие сайты остаются доступны. Отдельно проверь production-сборку маркетплейса.
