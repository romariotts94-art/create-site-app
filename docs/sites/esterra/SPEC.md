# ESTERRA — запуск 1 / фундамент и вертикальный срез

## Цель

ESTERRA — отдельный продаваемый продукт внутри каталога `create-site-app`: российский marketplace недвижимости для покупки, долгосрочной аренды и посуточной аренды.

## Аудитория и роли

- Клиент: ищет объект, открывает карточку, отправляет заявку.
- Оператор: получает заявку из `inquiries` для дальнейшей обработки.
- Администратор: следующий этап; в запуске 1 доступ к операционным действиям не добавляется.

## P0 первого запуска

1. Рабочий каталог ESTERRA виден в существующем каталоге BRAVE 365.
2. Серверная БД хранит объекты и заявки.
3. Поиск фильтрует по типу сделки, тексту, цене и комнатам.
4. Карточка объекта показывает реальные поля из API.
5. Заявка проходит клиентскую и серверную валидацию и сохраняется в SQLite.
6. Ошибка API не маскируется успешным состоянием.

## Границы

В этом запуске нет аккаунтов, ролей, платежей, бронирования, загрузки изображений и production-развёртывания отдельного API. Эти функции не имитируются. Внешние изображения Unsplash используются как визуальные seed-материалы и должны быть заменены/лицензированы заказчиком перед коммерческой передачей.

## Researcher findings

Проверены официальные публичные материалы и интерфейсные паттерны:

- [ЦИАН](https://www.cian.ru/) подтверждает базовые направления продажи и аренды и ценность поиска по карте.
- [Яндекс Недвижимость](https://realty.yandex.ru/moskva/kupit/kvartira/) показывает комбинацию типа сделки, объекта, комнат, цены, района/метро, карты, сортировки и быстрых фильтров; [справка поиска](https://yandex.ru/support/realty/ru/search/) фиксирует продажу и аренду как основные типы сделки.
- [Самолёт](https://samolet.ru/project/oktyabrskaya-98/) показывает для первичного рынка связку проекта, корпуса, площади, отделки и стадии готовности; [ипотечный сценарий](https://samolet.ru/faq/voprosy-o-pokupke/kak-vzyat-ipoteku/) ведёт от выбора к бронированию и заявке.
- [Booking.com Demand API](https://developers.booking.com/demand/docs/accommodations/search-for-available-properties) задаёт для посуточного сценария даты, гостей, локацию, доступность, фильтры и сортировку.

Вывод для ESTERRA: P0 начинается с явного типа сделки, серверной выдачи и фильтров, компактной карточки с ключевыми параметрами, подробного объекта и проверяемой заявки. В следующем запуске посуточный режим должен получить даты, гостей, доступность, правила отмены и итоговую цену до отправки заявки.

## Локальный запуск

```text
node sites/esterra/server.mjs
```

Открыть `http://127.0.0.1:4175/esterra/`. API: `/api/esterra/health`, `/api/esterra/properties`, `/api/esterra/inquiries`.
